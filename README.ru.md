# BVP Solver — универсальный решатель краевых задач для ОДУ

**Язык / 语言:** [简体中文](README.md) · [Русский (эта страница)](README.ru.md) · [Двуязычная техническая документация](docs/bilingual/README.md)

[![CI](https://github.com/wuy503797-collab/bvp/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/wuy503797-collab/bvp/actions/workflows/ci.yml)

BVP Solver — учебная программа для численных экспериментов с краевыми задачами для систем ОДУ первого
порядка. Она использует Python, SciPy, SymPy, PyQt5 и Matplotlib и предоставляет метод стрельбы, метод
продолжения по параметру, GUI, безоконный Python API, загрузку задач JSON, интерактивные графики и
атомарный экспорт результатов.

Проект продолжает развиваться. Текущие свидетельства охватывают перечисленные ниже аналитические,
сконструированные и учебные задачи, но не доказывают корректность любого BVP. Программа не предназначена
для производственных или критичных по безопасности расчётов.

## Основные возможности и граница корректности

- неизменяемые `BVPProblem`, `SolverConfig`, `BVPResult` и API ядра без побочных эффектов Qt;
- метод стрельбы с `root` → `least_squares` fallback и продолжение с фиксированным числом шагов;
- ограниченный AST-to-SymPy язык математических выражений без выполнения произвольного Python;
- раздельные допуски задачи Коши, нелинейного метода, Jacobian и итоговых краевых условий;
- снимки запросов GUI, происхождение результатов, кооперативная отмена и тесты жизненного цикла;
- структурированные события, метаданные, счётчики, единая схема JSON/TXT и атомарная запись.

Безопасный разбор, успешное завершение оптимизатора или прохождение одной базы не означает, что любой BVP
имеет решение. Итог должен одновременно пройти задачу Коши, конечность, состояние алгоритма и
покомпонентную проверку краевых условий.

## Снимок запроса, история и график

Нажатие «Решить» создаёт неизменяемый `SolveRequest` с уникальным `request_id`, задачей, конфигурацией и
метаданными. Последующие правки или смена задачи не меняют уже запущенный запрос. Успешный итог сохраняется
как `SolveRecord`; отказ и отмена сохраняют диагностику, но не входят в успешную историю.

График использует замороженные кривые и переменные каждой записи, а не текущий редактор или изменяемый
dense output. Поэтому несколько совместимых результатов можно отмечать одновременно: это относится не
только к одной задаче с другим начальным приближением, но и к изменениям коэффициентов ОДУ, краевых целей,
известных начальных значений, времени, метода решения, метода задачи Коши и допусков. Несовместимая
размерность или семантика координат исключается с явной диагностикой.

Отмена кооперативна. Выполняемый отдельный вызов SciPy `solve_ivp` нельзя немедленно прервать; отмена
обрабатывается после возврата управления на ближайшей контрольной точке. `QThread.terminate()` не
используется.

## Безоконный API

```python
from bvp_core import BVPProblem, SolverConfig, solve_bvp_problem

problem = BVPProblem(
    name="Scalar exponential",
    odes=["x"],
    var_names=["x"],
    boundary_conditions=["x0_T - E"],
    known_indices=[],
    unknown_indices=[0],
    known_values={},
    initial_guess=[0.5],
    t_start=0.0,
    t_end=1.0,
)
config = SolverConfig(
    method="shooting",
    eps=1e-8,
    boundary_atol=1e-8,
    boundary_rtol=0.0,
)
result = solve_bvp_problem(problem, config)
print(result.success, result.p_opt, result.boundary_residual_norm)
```

`bvp_core` не импортирует `main.py` или Qt и не создаёт окно. Ошибка определения задачи порождает
`BVPValidationError`; ожидаемый численный отказ возвращает структурированный `BVPResult(success=False)`.

## Математическая постановка

Рассматривается система

\[
\dot{x}=f(t,x),\qquad t\in[t_0,T],\qquad p\in\mathbb{R}^k.
\]

Неизвестные начальные компоненты представлены параметром `p`. После решения задачи Коши определяется

\[
\Phi(p)=R\!\left(x(t_0;p),x(T;p)\right),\qquad \Phi(p)=0.
\]

Число компонент невязки должно совпадать с числом неизвестных. Даже при совпадении размерности задача
может иметь несколько решений, не иметь решения, пересекать сингулярность, быть жёсткой или зависеть от
начального приближения.

## Метод стрельбы и продолжение

```text
p → IVP → boundary residual → root → least_squares fallback
  → candidate → independent final IVP → final boundary acceptance
```

Метод стрельбы сначала применяет `scipy.optimize.root(method="hybr")`, затем при необходимости
`scipy.optimize.least_squares`. Кандидат всегда заново интегрируется и проверяется по исходной невязке.

Метод продолжения по параметру строит гомотопию от легко удовлетворяемой невязки к исходной и проходит
фиксированное число шагов. В каждом шаге используется демпфированный метод Ньютона, Jacobian по параметрам
вычисляется прямой конечной разностью. Ошибка задачи Коши, разности, Newton или шага продолжения явно
передаётся. Адаптивного шага и продолжения по псевдодуге нет.

## Итоговый критерий успеха

```text
success = ivp_success AND finite_success AND boundary_success AND algorithm_success
optimizer_success != mathematical BVP success
```

Отдельная итоговая задача Коши должна достичь конца; параметры, время, состояние и невязка должны быть
конечными; каждая компонента границы должна пройти свой допуск; сам метод стрельбы или продолжения не
должен завершиться отказом. Статус оптимизатора остаётся диагностикой, а не математической приёмкой.

## Допуски

- `ivp_rtol`, `ivp_atol` управляют `solve_ivp`;
- `root_tol` управляет остановкой `root`;
- `least_squares_ftol`, `least_squares_xtol`, `least_squares_gtol` управляют fallback;
- `continuation_residual_tol` задаёт порог Newton при продолжении;
- `jacobian_relative_step` задаёт относительное возмущение прямой разности;
- `boundary_atol`, `boundary_rtol`, `boundary_scales` управляют только итоговой границей.

Покомпонентный критерий:

\[
|\Phi_i|\leq \texttt{boundary\_atol}
+\texttt{boundary\_rtol}\,s_i.
\]

Масштабы не переоценивают невязку внутри оптимизатора. Поле совместимости `eps` сохраняет старое
отображение, а явное поле переопределяет только свой численный процесс.

## Ограниченный язык выражений

```text
string → ast.parse(mode="eval") → AST whitelist
       → direct SymPy construction → lambdify(modules="numpy")
```

Производственный строковый вход не использует Python `eval`, `exec`, `parse_expr` или `sympify`.
Разрешены только перечисленные операторы, функции, константы и символы контекста с ограничениями
сложности. Атрибуты, индексы, контейнеры, lambda, неизвестные и приватные имена отклоняются.

Безопасная грамматика не означает численную корректность. Например, `1/(t-0.5)` синтаксически допустимо,
но интегрирование через `t=0.5` должно завершиться контролируемым отказом.

## Наблюдаемость и экспорт

`run_id` идентифицирует вычислительный запуск, `request_id` — пользовательский запрос, а
`problem_signature` — стабильный SHA-256 нормализованной задачи. `RunContext`, `RunMetadata` и
`SolverCounters` хранят время, среду, статус и работу IVP/`Phi`/Jacobian/оптимизаторов.

Ядро выдаёт структурированные события через `logging`, но по умолчанию не вызывает `basicConfig`, не
создаёт файл журнала и не пишет в stdout/stderr. Приложение само устанавливает handler.

JSON и TXT используют общий `CanonicalExportRecord` со схемой `bvp-result-v1`. JSON — строгий UTF-8 с
`allow_nan=False`, TXT — читаемое резюме тех же фактов. Оба формата применяют временный файл, `fsync` и
атомарный `os.replace`.

## Численная валидация

```bash
python scripts/run_numerical_validation.py
```

Проверяются:

- `x'=x, x(1)=e` с точным `x(t)=exp(t)` и `x(0)=1`;
- осциллятор `x'=v, v'=-x` с `sin(t), cos(t)` и `v(0)=1`;
- сконструированное `y=t^3-2t+1`, `v=3t^2-2`, `v(0)=-2`.

На 201 точке сравниваются параметр, состояние, RMS, граница и Simpson-подобный ODE defect:

\[
D_i=y(t_{i+1})-y(t_i)-\frac{h_i}{6}
\left[f_i+4f(t_{i+1/2},y(t_{i+1/2}))+f_{i+1}\right].
\]

Это независимо сконструированный показатель численной согласованности, но его состояния происходят из
того же dense output `solve_ivp`. Поэтому он не является полностью внешней проверкой или строгой
апостериорной оценкой погрешности.

## Задача 26.1 и несколько ветвей

В задаче о двух телах состояние `(x,y,vx,vy)` удовлетворяет

\[
x'=v_x,\quad y'=v_y,\quad v_x'=-x/r^3,\quad v_y'=-y/r^3,
\quad r=\sqrt{x^2+y^2}.
\]

Дано `x(0)=2`, `y(0)=0`; требуется `x(7)=1.0738644361`, `y(7)=-1.0995343576`. Неизвестны
`vx(0),vy(0)`: два параметра и две невязки. Метод стрельбы и продолжение подтверждают две разные
допустимые ветви. Это не перечисление всех решений и не гарантия сходимости из любого приближения.

Подробности всех задач 26.1–26.5 приведены в
[руководстве по задачам](docs/bilingual/task-guide.ru.md).

## Негативные проверки

- `x(T)^2+1=0` не имеет вещественного корня и должен завершаться отказом;
- `x'=1/(t-0.5)` на `[0,1]` должен передать диагностику отказа задачи Коши;
- один неизвестный параметр и две невязки должны отклоняться до SciPy.

Эти проверки не позволяют оптимизатору, неполному интегрированию или неконечному состоянию создать ложный
успех.

## Известные ограничения

1. Jacobian по параметрам использует прямую конечную разность;
2. продолжение имеет фиксированное число шагов и не реализует pseudo-arclength;
3. текущий вызов `solve_ivp` нельзя немедленно отменить;
4. задачи 26.2–26.5 не имеют аналитической истины;
5. задача 26.1 не перечисляет все ветви;
6. ODE defect не является строгой апостериорной оценкой;
7. расширенные допуски ограниченно редактируются в GUI;
8. программа предназначена только для обучения и численных экспериментов;
9. программа не предназначена для критичных по безопасности применений;
10. лицензия проекта пока не определена.
