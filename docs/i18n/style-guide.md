# 中俄技术文档翻译风格指南

## 1. 目标与语言代码

当前文档支持 `zh-CN` 和 `ru-RU`。中文是项目主 README 语言；俄文是完整镜像语言。译文应准确、
自然并适合数值分析、常微分方程和 Python 工程语境，不逐词机械对应。

## 2. 不翻译的内容

以下内容必须逐字保留：Python/API 标识符、JSON 字段、文件路径、命令、schema 名、版本号、Git SHA、
数值常量和公式符号。例如 `solve_ivp`、`least_squares`、`BVPResult`、`bvp-result-v1`、
`examples/tasks/26_1_two_body.json` 与 `2ac1a20`。

## 3. 术语与语气

- 使用[术语表](glossary.zh-ru.md)中的首选俄语，不混用同义词。
- 对能力使用可验证陈述；对限制使用明确否定，不暗示尚未实现的功能。
- 不把“优化器终止”写成“边值问题已经求解”。
- 不把 ODE defect 称为独立外部验证或严格误差界。
- “日志”表示事件流能力，不暗示程序默认创建日志文件。
- 项目定位为教学与数值实验软件，不使用安全关键或生产就绪措辞。

## 4. 当前文档与历史翻译

`docs/bilingual/` 描述当前 `main`。`docs/translations/v2.10/report.ru.md` 只翻译
`docs/reports/v2.10/report-source.md` 对应的历史软件快照：测试数保持 285，软件提交保持
`2ac1a20`，旧目录事实不因 Phase 13 改写。翻译文件的新增不创建 v2.11，也不修改报告 revision。

## 5. Markdown 对齐规则

- 文档对使用相同编号的二级标题，并尽量保持相同数量的公式和代码块。
- 相对链接从各自文件位置解析，避免本机绝对路径。
- 公式中的变量和不等式完全一致；自然语言解释可以按俄语习惯调整语序。
- 链接文字可翻译，目标路径不可翻译。
- 不保留任何表示译文尚未完成的占位符。

## 6. 许可证措辞

仓库尚无 `LICENSE`。只可写“许可证尚未决定”或“Лицензия проекта пока не определена”。
不得使用任何暗示已经开放授权、可自由使用或可自由分发的措辞。

## 7. 变更边界

文档本地化不授权修改算法、容差、表达式策略、任务数学、GUI 生命周期、CI workflow、版本映射或
冻结报告。本阶段只记录 GUI 当前语言覆盖，不实现新的 GUI i18n。
