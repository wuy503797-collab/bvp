# Тестирование, CI и проверка репозитория BVP Solver

[中文版本](testing.zh-CN.md) · [Двуязычный указатель](README.md)

## 1. Текущая база тестов

В начале Phase 14 текущая ветка `main` содержит 307 тестов pytest с целевыми 0 warnings. Тесты разделены
на core, numerical, GUI, integration и проверки репозитория/выпуска. Число 285 в историческом отчёте v2.10
относится к снимку `2ac1a20`: его нельзя выдавать за текущий счётчик и нельзя менять на 307 в переводе.

## 2. Уровни тестирования

- `tests/core/`: модели, API, перенос решателя, безопасность выражений, допуски, запросы, метаданные,
  производительность и сериализация;
- `tests/numerical/`: аналитические и сконструированные решения, чувствительность и метрики;
- `tests/gui/`: жизненный цикл вне экрана, политика warnings, изоляция нескольких кривых и приёмка;
- `tests/integration/`: контракт экспорта `bvp-result-v1`;
- верхний уровень: база, закрытые известные отказы, приёмка результата, раскладка задач и готовность.

Негативные задачи находятся только в `tests/fixtures/tasks/`. Пользовательские примеры лежат в
`examples/tasks/`; тесты не должны зависеть от старых JSON в корне.

## 3. Локальный pytest

```bash
python -m pytest -q
```

Для GUI задаётся `QT_QPA_PLATFORM=offscreen`; тесты не пропускаются из-за отсутствия дисплея. Отказ теста
остаётся отказом: проект не использует `continue-on-error` или глобальный warning filter для сокрытия
проблемы.

## 4. Специализированные сценарии проверки

```bash
python scripts/run_baseline.py
python scripts/run_numerical_validation.py
python scripts/run_expression_security.py
python scripts/run_tolerance_validation.py
python scripts/run_observability_validation.py
python scripts/run_performance_validation.py --ci
```

Базовый сценарий проверяет 26.1 и передачу отказов; остальные — аналитические/сконструированные решения,
политику выражений, допуски, метаданные/экспорт и детерминированный контракт производительности. Единая
команда `python scripts/run_ci_validation.py` последовательно запускает зависимости, импорт, компиляцию,
pytest, специализированные сценарии и гигиену репозитория.

## 5. Матрица GitHub Actions

`.github/workflows/ci.yml` фактически охватывает:

1. Windows / Python 3.11 с диапазонами зависимостей;
2. Ubuntu / Python 3.11 с диапазонами зависимостей;
3. Ubuntu / Python 3.11 с точными прямыми эталонными зависимостями.

Соответствующие job выполняют `pip check`, импорт без warnings, компиляцию, полный pytest, GUI вне экрана
и сценарии проверки. Только реальный Success удалённого workflow означает «CI прошёл»; локальный PASS не
заменяет удалённую запись.

## 6. Проверка двуязычной документации

```bash
python scripts/check_bilingual_docs.py
```

Проверяются пары файлов, нумерованные заголовки, относительные пути, разумное число формул/блоков кода,
исторические SHA, языковые ссылки README, двуязычный указатель, ключевые термины и отсутствие маркеров
незавершённого перевода. Скрипт проверяет структуру и факты, но не оценивает русскую грамматику.

## 7. Гигиена репозитория

```bash
python scripts/check_repository_hygiene.py
git diff --check
```

Проверка читает tracked/visible пути и ищет среды, кэши, временные файлы, вероятные секреты, локальные
абсолютные пути, битые ссылки README, регистр, крупные файлы и старые корневые задачи. Семь пользовательских
снимков экрана Phase 14 остаются неотслеживаемыми: они не перемещаются, не переименовываются и не входят
в документацию. `git diff --check` проверяет пробельные ошибки.

## 8. Обслуживание инфраструктуры CI

Примечания GitHub Actions о переходе Node.js 20→24 — низкоприоритетный неблокирующий долг инфраструктуры,
зарегистрированный в [`docs/maintenance.md`](../maintenance.md). Его статус `DEFERRED` не меняет текущий
CI PASS; после оговорённого триггера официальные Actions обновляются отдельной фазой, не вместе с
численным алгоритмом или локализацией.

## 9. Граница выпуска

В репозитории нет `LICENSE`. Поэтому успешные тесты и CI не завершают юридическую готовность:
`release_readiness_status=PENDING_LICENSE`. Эта фаза не выбирает лицензию, не создаёт tag/Release, не
повышает версию программы и не начинает материалы защиты курса.
