# Система численной валидации BVP Solver

[中文版本](validation.zh-CN.md) · [Двуязычный указатель](README.md)

## 1. Принцип валидации

`success=True`, остановка оптимизатора, малая краевая невязка и гладкий график — разные свидетельства.
Система объединяет аналитический oracle, сконструированное решение, отдельную итоговую задачу Коши,
покомпонентную проверку границы, численную согласованность с ОДУ, негативные входы, чувствительность к
допускам и детерминированные счётчики. Это подтверждает только проверенные задачи и пороги, а не любой BVP.

## 2. Аналитические решения

Для скалярной задачи `x'=x, x(1)=e` точное решение `x(t)=exp(t)`, неизвестно `x(0)=1`; метод стрельбы и
метод продолжения по параметру сравниваются по параметру, всей траектории и границе. Для осциллятора

\[
x'=v,\qquad v'=-x,qquad x(0)=0,\quad x(\pi/2)=1
\]

точное решение `x=sin(t), v=cos(t)`, неизвестно `v(0)=1`. Эти тесты обнаруживают ошибки траектории,
которые нельзя увидеть по одной конечной точке.

## 3. Сконструированное решение

Сначала задаётся

\[
y(t)=t^3-2t+1,\qquad v(t)=3t^2-2,
\]

затем строятся `y'=v, v'=6t` и согласованные краевые условия. Точный неизвестный параметр равен
`v(0)=-2`. Такой тест одновременно проверяет параметр, состояние, границу и ОДУ и не требует закрытой
формы учебной задачи.

## 4. Метрики и ODE defect

На 201 фиксированной точке вычисляются ошибка параметра, максимальная и RMS-ошибка состояния, норма
краевой невязки, максимальный компонентный defect, RMS defect и максимальный defect на единицу длины.
Между соседними точками применяется показатель типа Симпсона:

\[
D_i=y(t_{i+1})-y(t_i)-\frac{h_i}{6}
\left[f_i+4f(t_{i+1/2},y(t_{i+1/2}))+f_{i+1}\right].
\]

Он не копирует краевую невязку или поле `success`, а заново вызывает ОДУ, поэтому это независимо
сконструированный показатель численной согласованности. Однако состояния в середине взяты из того же
dense output `solve_ivp`: показатель не является полностью внешней проверкой интегратора и не задаёт
строгую апостериорную оценку погрешности.

## 5. Допуски и проверка краевых условий

Валидация отдельно проверяет `ivp_rtol/atol`, `root_tol`, три допуска least-squares,
`continuation_residual_tol`, `jacobian_relative_step` и поля краевой проверки, чтобы их семантика не
смешивалась. Для каждой компоненты требуется

\[
|\Phi_i|\leq a_{\mathrm{tol}}+r_{\mathrm{tol}}s_i.
\]

Масштаб участвует только в итоговой проверке и не меняет исходную невязку. Эквивалентность legacy `eps`
и явных полей проверяет совместимость; эксперимент чувствительности наблюдает тенденцию ошибки, но не
требует строгой монотонности округления или числа вызовов.

## 6. Негативная валидация

- нет вещественного корня: `x(T)^2+1=0` обязан вернуть отказ и невязку, а не принять остановку оптимизатора;
- сингулярная задача Коши: `x'=1/(t-0.5)` на `[0,1]` сохраняет место остановки и диагностику SciPy;
- переопределённый вход: один неизвестный и две невязки отклоняются до SciPy из-за размерности;
- неконечный кандидат, отказ продолжения и слишком большая итоговая невязка не входят в успешную историю,
  график или успешный экспорт.

## 7. Задача 26.1 и несколько ветвей

Для 26.1 метод стрельбы даёт начальную скорость около `[0,0.50000001]`, а продолжение — около
`[0.45107812,-0.29941864]`; обе конечные нормы невязки меньше `1e-8`. Это подтверждает как минимум две
численно проверенные ветви для одной конечной позиции, но не доказывает единственность и не перечисляет
все ветви.

## 8. Свидетельства согласованности производительности

После удаления бесполезного интегрирования вариационной матрицы число IVP для continuation 26.1 снизилось
с 874 до 600, а `nfev` — с 131732 до 94200; максимальное отличие массивов Jacobian равно 0. Повторное
использование `Phi_current` и удаление лишней работы не изменили формулу прямой разности. Время служит
диагностикой конкретной машины, а не межмашинной гарантией.

## 9. Воспроизводимые команды и ограничения

```bash
python scripts/run_numerical_validation.py
python scripts/run_tolerance_validation.py
python scripts/run_performance_validation.py --ci
```

Эти команды не создают отсутствующую аналитическую истину для 26.2–26.5. Валидация ограничена прямыми
конечными разностями, фиксированным продолжением, общим dense output, плавающей арифметикой платформы и
конечным набором задач. Программа пригодна только для обучения и численных экспериментов.
