# Руководство пользователя BVP Solver

[中文版本](user-guide.zh-CN.md) · [Двуязычный указатель](README.md)

## 1. Установка

Официальная проверенная база — Python 3.11. Рекомендуется отдельная среда с зависимостями разработки:

```powershell
py -3.11 -m venv .venv-clean
.\.venv-clean\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv-clean\Scripts\python.exe -m pip check
```

Для одного GUI/API достаточно `requirements.txt`; эталонные точные прямые зависимости находятся в
`requirements-lock.txt`. Эти файлы не являются полной хешированной блокировкой транзитивных зависимостей.

## 2. Запуск и выбор языка

```bash
python main.py
```

GUI сейчас запускается на русском и содержит меню переключения китайского/русского. Некоторые строки
жёстко заданы на китайском, русском или английском, поэтому это ещё не полная локализация. В этой фазе
реализация языков GUI не изменялась.

## 3. Загрузка и сохранение задач

Кнопка «Загрузить» открывает JSON. Начать можно с
[`examples/tasks/26_1_two_body.json`](../../examples/tasks/26_1_two_body.json) или
[`examples/tasks/textbook_problems.json`](../../examples/tasks/textbook_problems.json).
Обычные учебные задачи лежат в `examples/tasks/`; `tests/fixtures/tasks/` содержит намеренно негативные
входы автоматических тестов и не предназначен как пользовательский пример. Имя сохранения по умолчанию —
`bvp_task_collection.json`.

## 4. Редактирование математической задачи

Укажите размерность, имена переменных, правую часть каждого ОДУ, конечное время `T`, известные начальные
значения, приближения неизвестных, краевые условия, метод задачи Коши и shooting/continuation. В краевых
условиях применяются псевдонимы `x0_0`, `x0_T`, а в ОДУ и вспомогательных выходах — имена переменных.
Разрешён только белый список выражений; степень записывается `**`, а не `^` или неявным умножением.

Число неизвестных начальных компонент должно совпадать с числом краевых условий. `eps` остаётся входом
совместимости; полная расширенная настройка допусков доступна главным образом через JSON или Python API,
поскольку GUI не редактирует все поля.

## 5. Решение, отмена и диагностика

После «Решить» вход фиксируется в `SolveRequest`. Редактирование или смена задачи не меняет уже запущенный
запрос. Отмена кооперативна: выполняемый `solve_ivp` может сначала вернуться, после чего ближайшая
контрольная точка обработает отмену. При отказе изучайте статус, диагностику IVP, невязку и сообщение.
Успех оптимизатора не означает, что краевая задача прошла итоговую проверку.

## 6. Несколько результатов и график

Каждый успешный результат имеет отдельный снимок. Можно одновременно отметить совместимые записи:
разные ветви 26.1 после изменения только начального приближения, а также результаты с другими числовыми
коэффициентами, краевой целью, известным начальным значением, временем, методом или допуском. Старая
кривая не меняется из-за редактора или нового dense output. Несовместимая размерность, семантика переменных
или времени исключается с диагностикой.

## 7. Экспорт результата

JSON и TXT экспортируют снимок запроса выбранного результата по схеме `bvp-result-v1`. JSON — строгая
машинная запись UTF-8, TXT — читаемое резюме из того же источника. Запись использует временный файл и
атомарную замену; экспорт истории не читает текущий редактор и не создаёт нестандартные NaN/Infinity.

## 8. Безоконный API

```python
from bvp_core import BVPProblem, SolverConfig, solve_bvp_problem

problem = BVPProblem(
    name="Scalar exponential",
    odes=["x"], var_names=["x"],
    boundary_conditions=["x0_T - E"],
    known_indices=[], unknown_indices=[0], known_values={},
    initial_guess=[0.5], t_start=0.0, t_end=1.0,
)
result = solve_bvp_problem(problem, SolverConfig(method="shooting", eps=1e-8))
print(result.success, result.p_opt, result.boundary_residual_norm)
```

Импорт `bvp_core` не требует `QApplication`. Ошибка определения порождает `BVPValidationError`, а
ожидаемый численный отказ возвращает `BVPResult(success=False)`.

## 9. Границы использования

Один успешный запуск не доказывает единственность; изменение начального приближения не обязано сохранять
ветвь. У 26.2–26.5 нет аналитической истины, а ODE defect не является строгой апостериорной оценкой.
Программа предназначена для обучения и численных экспериментов, не для критичных по безопасности
решений. Лицензия проекта пока не определена, и права нельзя вывести из отсутствия файла `LICENSE`.
