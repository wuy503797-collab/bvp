## 2. Где вычисляются Phi и Jacobian

Класс `BVPSolver`, файл `bvp_core/solver.py`:

- `_p_to_state(p)` добавляет известные компоненты к неизвестному вектору `p`.
- `_Phi(p)` вызывает `_solve_ivp(...)` для исходной системы по времени `t`,
  затем `bc_residual(x0_full, xT_full)`. Это и есть `Phi(p)`.
- `_dPhi_dp(p, scheme=..., step=...)` вычисляет Jacobian численно.

Jacobian **не аналитический и не получен интегрированием вариационной системы**.
По умолчанию сохранена прежняя передняя конечная разность:

```text
J[:, j] = (Phi(p + h e_j) - Phi(p)) / h
h = max(1e-7, effective jacobian_relative_step)
```

Старый `solve_continuation()` вызывает эту функцию без новых аргументов,
поэтому его математическая схема и счётчики не изменены.
Новый метод вызывает ту же функцию с `scheme="central", step=1e-5`:

```text
J[:, j] = (Phi(p + h e_j) - Phi(p - h e_j)) / (2 h)
```

Это по-прежнему конечные разности, но симметричные, с погрешностью усечения
O(h²) для достаточно гладкой Phi. Такая опция добавлена специально для
интегрирования уравнения по mu без Newton-коррекции. Исходная передняя
разность с h=1e-4 давала конечную норму около 1.17e-4; уменьшение только
допуска интегратора по mu эту ошибку не устраняло. Очень малый h также
не гарантирует улучшения из-за вычитания близких чисел и ошибок state IVP.

## 3. Уравнение дифференциального МПП

Вводим вспомогательный параметр mu, который не является физическим временем:

```text
Phi(p(mu)) = (1 - mu) Phi(p0),    0 <= mu <= 1.
```

При дифференцировании правая часть даёт постоянный вектор `-Phi(p0)`:

```text
J(p(mu)) dp/dmu = -Phi(p0),    p(0) = p0.
```

В `solve_differential_continuation()` начальный вектор невязки вычисляется
перед интегрированием: `phi_p0 = self._Phi(p0)`. Замыкание `mu_rhs` передаёт
тот же `phi_p0` при каждом вызове `differential_continuation_rhs`.
Вычисления `Phi(p ± h e_j)` внутри Jacobian нужны для производной и не
заменяют фиксированный правый вектор гомотопии.

`differential_continuation_rhs(mu, p, phi_p0, ...)` делает три действия:

1. Получает `jacobian = self._dPhi_dp(parameters, scheme="central", step=...)`.
2. Формирует `right_hand_side = -np.asarray(phi_p0, dtype=float)`.
3. Возвращает `dp_dmu = np_solve(jacobian, right_hand_side)`.

Почему не inverse: если A невырождена, решение Ax=b математически равно
A⁻¹b. Но для одного b достаточно решить систему через факторизацию матрицы;
строить все элементы обратной матрицы не требуется. Это избегает лишних
операций и дополнительных ошибок округления. `solve` не устраняет проблему
плохой обусловленности: здесь проверяется `np.linalg.cond(jacobian)`.
Нефинитная, вырожденная или слишком плохо обусловленная матрица приводит
к отказу; нет скрытого перехода к псевдообратной или least squares.
Порог обусловленности `1e12` - явная инженерная защита, не универсальная
математическая гарантия для всех масштабов задачи.

## 4. Где интегрируется mu

В `BVPSolver.solve_differential_continuation()`:

```python
mu_sol = solve_ivp(
    mu_rhs, [0.0, 1.0], p0,
    method=mu_method, dense_output=True,
    rtol=mu_rtol, atol=mu_atol,
)
```

Фактические настройки проверенного запуска:

| Уровень | Настройки |
|---|---|
| Исходный state IVP по t | RK45, rtol=1e-8, atol=1e-9 |
| IVP для параметров по mu | RK45, rtol=1e-10, atol=1e-12 |
| Jacobian нового метода | central, абсолютный шаг h=1e-5 |
| Предел condition(J) | 1e12 |
| Краевая приёмка | atol=1e-8, rtol=0, для каждого компонента |

Метод, допуски, шаг, границы интегрирования, `p0`, `p1`, `mu_status`,
`mu_message`, `mu_reached_1`, `rhs_evaluations` и траектория сохраняются в
`solver_metadata["differential_continuation"]`. Настройки mu и центрального
шага можно явно передать методу; вызов через публичный API использует
показанные значения по умолчанию. Общее поле `effective_jacobian_relative_step`
описывает старую конфигурацию; фактический шаг нового метода находится в
`differential_continuation.jacobian_step`.

`p(0)` - переданное начальное приближение неизвестных скоростей.
`p(1)` - конечный вектор `p_final`, полученный из `mu_sol.sol(1.0)`.
`trajectory.p` имеет форму `(число параметров, число точек mu)`.
Если начальный вектор уже удовлетворяет границам, возвращается постоянная
траектория и `integration_skipped=True`, `rhs_evaluations=0`.

## 5. Повторная проверка исходной краевой задачи

`mu_sol.success` описывает только решение вспомогательной задачи Коши.
После получения `p_final` вызывается `_validate_final_candidate(...)`:

1. Заново интегрируется исходная система `_solve_ivp(..., purpose="final_validation")`.
2. Заново вычисляется `bc_residual(self._p_to_state(p), sol.y[:, -1])`.
3. `_build_validated_result()` применяет `evaluate_boundary_acceptance()`.

```text
success = ivp_success AND finite_success AND boundary_success AND algorithm_success
abs(residual_i) <= boundary_atol + boundary_rtol * boundary_scales_i
```

Это отдельное повторное вычисление, но оно использует тот же state IVP
и тот же код краевых условий; оно не является независимым внешним решателем.
После приёмки результат преобразуется в `BVPResult` в `bvp_core/api.py`.
Метаданные, причины отказа, счётчики и время сохраняются. Отмена вызывает
`SolveCancelled`; публичный API добавляет `RunMetadata` отменённого запуска.

## 6. Отличие от прежнего метода

Новый метод, формула A задания:

```text
dp/dmu = -[Phi'(p)]^-1 Phi(p0).
```

Здесь численный IVP-интегратор выбирает шаги по mu и двигает параметры
по производной. На каждом вычислении RHS решается линейная система,
но не нелинейная краевая задача Newton-итерациями. В реализации нет
финального Newton-дополирования, которое могло бы скрыть ошибку mu-ODE.

Старый `solve_continuation()`, формула B задания:

```text
p_(j+1) = p_j - solve(Phi'(p_j), Phi(p_j) - (1 - mu_k) Phi(p0)).
```

Он выбирает дискретное mu_k, затем Newton-итерациями с демпфированием
решает нелинейное уравнение на этом фиксированном mu_k. Это не численное
интегрирование dp/dmu. Старый метод не удалён и не переименован.

## 8. 60 秒解释 / Объяснение за 60 секунд

**Русский.** Mu - вспомогательный параметр, который постепенно уменьшает
требуемую невязку от её начального значения до нуля. Я задаю
Phi(p(mu))=(1-mu)Phi(p0) и дифференцирую это равенство. Phi(p0) уже
вычислена и не зависит от mu, поэтому справа получается постоянный
вектор -Phi(p0). Слева по правилу цепочки получается Jacobian, умноженный
на dp/dmu. Я решаю эту линейную систему через solve, без явного inverse,
и интегрирую найденную производную от mu=0 до mu=1. При mu=1 правая
часть исходной гомотопии равна нулю, то есть получаем исходные краевые
условия. Из-за численных ошибок я обязательно заново решаю исходную
задачу Коши и проверяю фактическую краевую невязку.

**中文理解。** μ 是辅助参数，让要求的残差从初始残差逐渐降到零。
对同伦式求导后，右端是已经固定的 `-Phi(p0)`；左端由链式法则得到
Jacobian 乘 `dp/dμ`。解这个线性方程组就知道参数应该往哪个方向变化。
用 `solve` 直接求所需向量，不必构造整个逆矩阵。将参数从 μ=0 积分到
μ=1，理论上边界残差变为零；数值实现仍需重新积分原方程并严格验收。

## 9. 代码定位速查 / Пять мест в коде

下面五项都在 `bvp_core/solver.py` 的 `BVPSolver` 类中，用函数名即可定位。

| 教师要看的位置 | 函数与变量 |
|---|---|
| Phi(p) | `_Phi`: `sol`, `x0_full`, `xT_full`, `residual` |
| Phi'(p) | `_dPhi_dp`: `scheme`, `eps_jac`, `jac_matrix` |
| dp/dμ 的右端 | `differential_continuation_rhs`: `right_hand_side = -np.asarray(phi_p0, dtype=float)` |
| Jacobian 线性求解 | 同函数: `dp_dmu = np_solve(jacobian, right_hand_side)` |
| 对 μ 积分 | `solve_differential_continuation`: `mu_rhs`, `mu_sol = solve_ivp(...)`, `p_final` |

可当场解释的小修改：在直接调用 `solve_differential_continuation` 时将
`mu_rtol` 改为 `1e-9`，然后比较终端输出的残差与 RHS 次数；不能仅凭
积分完成就宣布成功，也不能为获得成功而放宽边界验收阈值。
